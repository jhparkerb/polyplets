# Engine re-audit — 2026-07-13 (regression sweep of the varint + kink engine)

Re-run of the [AUDIT-2026-06-28](AUDIT-2026-06-28.md) campaign against the
*current* engine. Since June the hot path moved from the TMA sweep to the
**varint record encoding + kink-carry kernel**, and the record path now injects
**diagonal-law closed forms** (`P_k`, k=0..16) that bank record values — new
surface the June audit predates. Same bug classes hunted: **regression** vs.
previously-working code / agreed mode, **sharp corner** (silent wrong result
without a magic incantation), **closed-form brute-force**, **design flaw**, and
**scaling/OOM** (fine at small n, bites at large n).

Method mirrored June: **five parallel read-only audits** — kink kernel, varint
data path, Go orchestrator, closed-form/diagonal injection, CLI/gates/g2 — each
adversarially trying to *disprove* every candidate before reporting. Findings
de-duplicated and severity-ranked below. Every fix is its own commit, **test-first
with the RED captured** (the failing test verified against a faithful revert of
the fix before the green version was committed).

Constraint honored: the box was running a Redelmeier a(22) enumeration throughout,
so the audit stayed read-only and the fixes were verified with **narrow, already-
built Go tests only** — no C++ builds or ASAN/gate suites launched (those are
deferred to when the box is free).

## Fixed this campaign

**G1 · "Stranded Frontier" — HIGH — `654413f`.**
`sweepHeight` / `sweepHeightKink` deleted each column's consumed frontier
(`removeRuns(oldFrontier)`) unconditionally, even when that column's per-column
checkpoint was interval-throttled away. The code comment "GC only after checkpoint
is written" was therefore false under the production `--checkpoint-every 300`: a
run of sub-interval columns (cheap head/tail columns) deletes the files the last
*persisted* checkpoint still names. A hard crash (OOM/reboot/SIGKILL) in that
window strands the checkpoint on deleted files → `--resume` fails loudly
(`map_worker: cannot read input`) and the whole height re-runs from col 0. Fails
loud (no miscount), hence HIGH not CRITICAL. Both audit passes (Go orchestrator +
kink) landed on it independently. Fix: `frontierGuard` retains the frontier the
last persisted checkpoint references and defers a consumed frontier's deletion
until a superseding checkpoint is written, while GCing unreferenced intermediate
frontiers eagerly (no disk leak). RED-first via `TestFrontierGuard*`; the existing
`TestKillResumeAllBoundaries` structurally couldn't catch it (it cancels only at
*written* checkpoint boundaries).

*Nuance:* production `dalby_term.sh` uses `--overlap-heights N` → `runOverlap`,
which checkpoints only at height boundaries and re-runs in-flight heights from
scratch, so it largely sidesteps G1. G1 bites sequential mode (`--overlap-heights
1`) with `--checkpoint-every > 0`. Fixed regardless — the invariant the code
asserted was simply false.

**V1 · "Varint Straggler" — MED — `cba29ec`.**
The varint migration (`f4edb3b`) updated the six POLYRUN count parsers but missed
a seventh: `sampleBodyKeys` still skipped each record's counts as a fixed
`length*wordBytes` (the pre-varint layout). Since counts are now LEB128 varint,
the byte stream desyncs after the first record and every sampled key is garbage
from mid-record. Not a miscount — the samples feed `BalancedCutsMulti`, which
sorts before cutting, so ranges still tile the key space; harm is a mis-placed cut
→ straggler. It is the `.idx`-absent fallback (tiny ≤64-record runs, or a large
file whose sidecar failed to open under fd pressure), so rare — but on a large
file without its `.idx` it produces exactly the straggler the balanced-cut work
exists to kill. Fix: width-agnostic `discardVarint` skip (also correct for u128
counts past u64). RED-first via `TestSampleBodyKeysVarintAligned`.

**D1 · "Silent Truncator, Redux" — MED — `1c4997f`.**
`hornerDiag` divided the diagonal-law Horner numerator by `k!` with a bare
truncating `num.Quo(...)` and no remainder check, then handed off to `applyPow3`.
`applyPow3` was deliberately given a `QuoRem`+panic guard so a bad value fails
closed — but that guard covers only the 3-power divide, and only its negative-
exponent branch; for positive-exponent record cells (n≥3k+1, e.g. a36's
`T(22,20)`) `applyPow3` merely multiplies. So the `k!`-divide was the *only* check
on the divide path, and a coefficient-transcription error that broke
`k!`-divisibility would be silently truncated into a wrong banked cell. Fix:
`QuoRem`+panic mirroring `applyPow3`. RED-first via
`TestHornerDiagKFactExactnessAssertion`; full diagonal suite (all wired `P_k`)
still green, so no legitimate cell trips the guard.

**X1 · "Unguarded Oracle" + X2 · stale ranges — LOW — `91ce963`.**
`gate-g2` (the g2 Redelmeier oracle's correctness gate) lived only in the manual
`make gates` target — absent from `ns-gates`, `ns-gate-fast`, and the pre-push
hook — so the recent g2 hot-kernel perf burst (L1..L4, dropped reachedUndo, all
independently verified correct in this audit) had no routine gate. Added to
`ns-gates`. Also corrected stale diagonal k-range comments (`j=0..12`/`k=0..10` →
`0..16`).

## Deferred (recorded, not blocking)

**K1 · "Unspillable Boundary" — MED, latent OOM.** The kink seed (`kink_stage==-1`)
and finalize (`kink_stage==-2`) rounds load their entire assigned key-range into a
`Run<W>` in RAM with **no spill path and no work-stealing** (`map_worker.cpp:245`
hard-sets `spill_bytes=0`; steal is gated off for seed/finalize at
`sweep.go:1162`). The header comment states this is "in-RAM per Design 14 Phase
2's scope (a(20)-gate scale never needs to spill)" — 16 terms behind the live
a(36) frontier. At a large-n peak column with a skewed key distribution
(`BalancedCutsMulti`'s open-ended last range is documented to skew ~9000×), a
single seed/finalize worker's range can hold a multi-GB slice with unbounded RSS →
OOM. Survived a36, so latent, not live. **Deferred**: it's a real design change
(thread a spill fallback through seed/finalize), and the project is in close-out
with engine-scaling work deprioritized ([[no-cloud-burst]], [[project-close-target]]).
Bites first at a37+ or on tighter-RAM boxes; watch the per-worker `--ram` budget
([[ram_budget_per_worker]]).

**V2 · u64 body-sum in `verify.go`.** `SumCountsInFile` accumulates via
`binary.ReadUvarint` into `uint64`; at u128 record magnitudes (a26+) it **errors
out** (loud fail, not a false pass), so the independent *value* verifier only
validates u64-range runs. The width-agnostic **CRC check still works at any
magnitude**, so the integrity backstop is intact. Consistent with the A2/A6
deferral lineage — a full independent value re-verification past a25 needs a
mod-p or big.Int producer. **Deferred.**

**V3/V4/V5 · C++ latent defensive gaps.** (V3) `decodeVarint` (`run.h:159`,
`runfile.h:424`) loops `shift += 7` with no width bound → UB on a corrupt/truncated
stream (trusted-internal-file path). (V4) `RunFileWriter` permits
`write_index && compress` together, which would desync `.idx` seek offsets —
**not currently reachable** (every call site pairs `compress` with
`write_index=false`); a `compress_ && write_index_` abort would close it. (V5)
`seekToKey` uses a hardcoded `uint8_t key[64]` rather than `SIGMAX` — safe at the
default `POLY_SIGMAX=32`. All three are one-line defensive asserts, but verifying
them needs a C++ build, deferred while the a(22) run holds the box. **Batch these
when the box is free** (`make gate-runfile` + `-Werror`).

## Noted (accepted posture, no code)

**C1 · Fitted-coefficient extrapolation.** `docs/proofs/diagonal-law.md` proves the
diagonal law's *shape* (degree ≤ k, onset n≥2k+1, integrality) for all k, but the
*monomial coefficients* of `P_k` are **fitted** (leading coeff from defect-gas
theory + universal symbols pinned by lower fits + a holdout), not derived. Each was
holdout-validated before wiring and reconfirmed here against swept data through
n=35 — but the record's genuine **extrapolation cells** (e.g. a36's `T(36,20)` via
`P_16`, confirmed nowhere; holdout was `T(35,19)`) have no independent check, and
**nothing in the code enforces that a newly-wired `P_k` carries a passing holdout**.
This is the direct generalization of June's deferred C1. Keep flagged whenever
`P_17`+ get wired; the D1 fix at least makes a *divisibility*-breaking
transcription error fail closed.

## June fixes verified still present (regression check)

The audits re-confirmed, in the current engine, that the June fixes did not rot:
refuse-at-start guards (`CheckCounterWidth`/`CheckResultWidth`, `Cores≥1`,
`require-cover` default true); resume config stamp+verify (now including the
kernel tag) with the edited-`--heights` double-count guard; Budget Blind (spill
sizes by resident cost), Index Hoard (index streams to `.idx.tmp`), Index Slurp
(on-disk binary search), Magic Misread (self-describing `.idx` header skip on both
sides), atomic publish (`.idx` renamed before data), CRC seeked-read contract, the
LOW-cluster CLI fixes (runcat non-zero exit, combine n>maxn refusal + a *new*
monotone-growth guard, seed-writer tag rejection), and A7 gate wiring. A2's big.Int
widening — DEFERRED in June — has since been **done** (`1a0ac2d`): accounting /
combine / predict / verify are `*big.Int` end-to-end.
