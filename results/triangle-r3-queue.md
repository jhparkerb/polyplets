# Round-3 idea queue — append-only

Opened 2026-08-12 by the lead, mid-round, because a fan-out that gives one idea
per lane a thorough look and then shrugs is not a search. **Ruling something out
is only half a lane's job; the other half is what the obstruction tells you to
try next.**

## Protocol

- **Append only.** Never edit or delete another agent's row. To close a row,
  append a new row citing the id you are closing.
- **Every agent that closes a candidate files successors.** Minimum two per
  closure, and "none — here is why the obstruction is terminal for this whole
  family" is an acceptable answer only when argued, not when convenient.
- A successor is worth filing if it is *different in kind*, not a parameter
  tweak of the thing you just killed. Ask: what would have to be different about
  the problem for this to work; is there an adjacent object where that holds;
  what did the obstruction prove about the family rather than the instance.
- Rows are cheap. File the half-formed ones — the triage pass ranks them, and an
  unfiled idea costs the round more than a bad row does.
- Anyone may file into any lane's territory. Cross-lane rows are wanted.

## Row format

    | id | idea, one line | origin | status | note |

`id` is `<lane>-<n>` (e.g. `L4-3`, `LEAD-1`). `origin` names the agent and what
spawned it — a closure, a measurement, a reading. `status` is OPEN, DISPATCHED,
CLOSED, or MERGED(id). `note` carries the reason on a closure, or the cost/level
guess on an open row.

## Standing rank order for the triage pass

1. clears both entry-ticket levels over clearing level 1 only;
2. reaches the band (H=15..21 at n=40) at all, exact or modular, over reaching
   only smaller n;
3. cheapest checker to a reader, per the standard.
