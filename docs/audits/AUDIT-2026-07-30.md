# Close-out audit — 2026-07-30 (post-a(40) sweep of the Second Wind engine + publish surface)

Third campaign, following [AUDIT-2026-06-28](AUDIT-2026-06-28.md) and
[AUDIT-2026-07-13](AUDIT-2026-07-13.md). Since July the surface moved again:
the **Second Wind** data-path burst (block-buffered I/O, Fan-In Tax, Mirror
Toll zstd framing, tmpfs fastmap, Overcommit Hydra phasing), the **P_17–P_19
diagonal wirings** and the Zero Harvest checkpoint fix, the **a(37)–a(40)
banking chain** (a(40) = final term, project closes), the **Lean
formalization** (polyplets/), and the **publish artifacts** (OEIS staging,
b-files, triangle, checkers). Same classes hunted — regression, sharp corner,
silent wrong result, scaling/OOM, design flaw — plus two new ones this
campaign because the project is at publish: **overclaim** (a stated check that
is weaker than its wording) and **evidence laundering** (a "verification" that
compares a formula against its own output).

Method mirrored the prior campaigns: **five parallel adversarial read-only
audits** — Second Wind C++ data path, orchestrator resume/phasing/fastmap,
diagonal injection, publish artifacts/checkers, Lean + strip second source —
each attacking its own candidates with code/git/data evidence before
reporting. The box was idle, so unlike July the auditors could *measure*:
purpose-built corruption/truncation/mixed-frame probes against the runfile
format, full independent recomputes of every wired P_k, a live re-run of both
paper checkers, `lake build --no-build` against the Lean tree, and a live
oeis.org fetch to settle the b-file provenance question.

  from the repo's own coefficient table against **176 non-circular triangle

  8,176 redundant observations — 0 conflicts. **No banked value depends on

  The a(39)→a(40) mass-holdout claim (P_0..P_18 confirmed by the real H21
  sweep, 19 rows) verified true from the artifacts, and P_18's holdout
  T(39,21) confirmed genuinely independent of its fit.
- **Publish numbers**: all 820 triangle cells, all 40 A006770 terms, all five
  companion b-files, all four Wave-2 drafts, and the report's Table 2
  recompute correctly — including three decorrelated routes (g2 Redelmeier
  live to n=13; fixed-height GFs H≤10 expanded to n=40, 355 cells; exact
  2-point rational P_k refit, 342 cells). Growth figures and all
  PROVENANCE-quoted cells verified.
- **Lean**: 0 sorry/axiom/unsafe across 10,705 lines; builds green at HEAD
  (8,592 jobs up-to-date); every axiom-footprint claim re-measured against
  the live kernel and confirmed; `PinGrand.lean` regenerates byte-identical;

The compressed-frontier format itself (Mirror Toll) survived every attack:
mixed frame sizes across the 64→256 default change, `.idx` seek validity on

seek/merge probes, all clean).

What the campaign did find: one HIGH silent-undercount hole in the reader
with no detector, one HIGH fail-open checker blind to 54% of the report's
Table 2, a reproduction trap that **three audits found independently** (the
recorded a(40) recipe now destroys its own strongest validation artifact),
and a cluster of evidence-laundering and staleness defects in the publish
surface. None of them touched a banked value; several would have embarrassed
the publication.

## The headline findings, in brief

**E1 · "Short Shrift" — HIGH.** `RunFileReader::next` returns `false` for
end-of-records, a truncated body, and a zstd checksum failure alike; no
caller compares records-read against the header count, and `finalize()`
warns-and-publishes on a failed count backpatch/flush (only `fwrite` got
`writeOrDie`; the `fseek`-flush and `fclose` legs are unchecked). Measured
with corruption/truncation probes: one flipped byte in a compression-2 file →
**0 of 3000 records on the production seeked path, silently**; a 500-byte
truncation → 2945 of 3000 records through a merge with no error. Reachable
via ENOSPC on the size-capped tmpfs the a(40) run actually used. No evidence
any banked value was hit — the chain revalidations (a(1)–a(39) recomputed in
the a(40) run) would almost certainly have caught a dropped shard — but this
is the one publish-relevant engine fix: a fail-closed abort in one place
covers truncation, lost-tail ENOSPC, checksum failure, and bit rot at once.

**P1 · "Grey Cell Blindspot" — HIGH.** `verify_technical_report.py`'s cell
regex `\\(num|textbf|g)\b` fails to strip `\g` before a digit (`\g10`), so
every gray-highlighted cell parses to `None` and is silently skipped: **42 of
78 Table 2 cells are never checked** while the tool prints "432 checks". All
78 re-parsed correctly against the triangle — no wrong number, pure fail-open.
Companion P2: strip a `\midrule` and 126 checks vanish silently (measured).
The fix also extends the pole-column check to all 342 in-onset cells (~10×
coverage, verified clean in the audit).

**D1 · "Phase C Phantom" — MED, found independently by three of the five
audits.** With P_19 now wired and the k-fence at 19, the *recorded a(40)
reproduction recipe* (`dalby_term.sh 40`, phase C = H21) no longer performs
the 36.4-hour real H21 sweep — it injects H21 from P_19, the formula fitted
to that very cell. The result is provably bit-identical (verified: the
closed-form H21 strip matches the real sweep on all 20 rows), but a re-run
silently destroys the project's strongest validation artifact (the P_0..P_18
mass holdout) and makes four shipped "P_19 is used for no banked term"
claims false-on-rerun. One-line fix plus a PROVENANCE reproduction note.

**D2/D3 · evidence laundering — MED.** `derive_pk_fast.py`'s holdout check
reads the lexically-first run containing a row — which is exactly the run
that *injected* that cell — so the printed wiring evidence for P_17/P_18
counted **zero real holdout points** (formula vs itself; P_19's `holdout(0)=
True` is vacuous). The real holdouts exist but are structurally invisible to
the script. Likewise `extract_pin_data.py` counts 27 formula-injected cells
as "verified against banked". July's C1 ("nothing enforces holdout-before-
wire") turns out to have been not merely unenforced but actively misreported.
The coefficients themselves were independently re-derived and are clean; the
Lean pin pipeline (`gen_grand_pin.py`) already guards this correctly
(`HMAX_ANCHOR=20`) — the standard existed and was applied in one generator
of two.

**O1 · "Ghost Checkpoint" — MED.** `writeCheckpoint` swallows write errors;
callers pass the *throttle* decision, not the *write outcome*, into July's
G1 `frontierGuard` — so a failed checkpoint write (ENOSPC at 363 GB peak was
the realistic regime) lets the guard GC the frontier files the surviving
on-disk checkpoint still names. G1's stranding shape, reintroduced on the
error path. Fail-loud, no miscount.

**S1–S4 · the strip second source, honestly scoped — MED.** The "413 cells,
0 mismatch" claim is exact and its provenance exemplary (blob-hash-verified).
But "~85–90% coverage" is a *cell* count that credits P_k formulas as a
second source (honest cell figure: 67%), and by **mass** the final terms are
nearly un-second-sourced — a(37) 9.1%, a(38) 5.5%, a(39) 2.5%, **a(40)
≈0%** — because the strip run stopped at n=36. The strip kernel is also the
same union-find algorithm as the repo's own column oracle (`transition.h`);
the load-bearing claim ("shares no enumeration with the kink kernel")
survives, the blanket "independent/fresh code" phrasings don't, and the
Python "twin" is a port, not an independent check. Sharper still, found
during the fix campaign (`7e5ab13`, resolved `3fbc7aa`): the banked strip
run is n≤36 as well as H≤14, so it touches **no cell of rows 37–40 at
all** — as banked, the strip second-sources **0%** of a(37)–a(40). The
audit's 9.1/5.5/2.5/0.0% figures turned out to be a *different, correctly
computed* quantity that had been mislabelled as strip coverage: the share
of each row that a closed form predicted first and a later real sweep then
confirmed — structurally 0 at a(40), whose closed-form cells start at H=22,
above every real sweep that will ever exist. Both quantities now live,
separately labelled, in PROVENANCE's corroboration-by-mass section. **The single highest-value remaining action found by
this campaign** — one command, ~8 h on dalby, no new code:
`./build/strip_tm 14 40 results/ns_a40/perheight` would lift second-sourced
mass on a(37)–a(40) to ~45–54%. Left to jasonp (hours-long job).

**a(40) corroboration by mass** (added to PROVENANCE by this campaign; the
number a referee most needs and no artifact previously stated):
H1–10 = 7.5% (verified here against the decorrelated fixed-height GFs),
H11–19 = **81.3% (no independent corroboration available)**, H20 = 4.2%
(byte-identical standalone re-sweep), H21 = 2.8% (real, but P_19's fit
point), H22–40 = 4.1% (closed forms with passed holdouts). This is what the
README's T2⁻ grade means, now quantified.
