# Engine audit — 2026-06-28 (regression sweep after the top-height incident)

*(Formerly `BUGS-OF-SHAME.md`. Commit messages reference items by code as
"BUGS-OF-SHAME A1", etc. — those codes are stable and used below.)*

Audit triggered after the next-system engine was caught brute-force-enumerating
the top height `H=maxn` (the single most expensive strip of every run) to
rederive the closed form `T(n,n)=3^(n-1)` — work the old engine had always added
by hand. That wasted ~16h of measured wall (≈half the a(20) revalidation; the
running a(21)'s H21 and counting) plus older instances, and stalled ayr.

Primary class hunted: **regression vs. previously-working code and the agreed
mode of operation.** Secondary nets: **sharp corners** (correct/fast behavior
requires a magic incantation) and **design flaws**.

## A. Regressions (primary class) — old engine / agreed mode did it; new system doesn't

**A1 · "The Phantom Cure" — CRITICAL / process: the top-height fix is uncommitted. → FIXED `2d782e2`.**
`contributeTopHeight` + the `mapPhase` guard + `topheight_test.go` exist only in
the working tree, not in HEAD. Every deployable binary (and the live dalby
a(21), rev `35eb9e1`) still brute-forces `H=maxn`. The fix is one `git commit`
from real.

**A2 · "The u64 Funnel" — CRITICAL: `--counter u128` buys nothing; the result pipeline truncates to u64. → GUARD `ca5b084`; big.Int widening DEFERRED.**
Workers compute u128, but `orchestrator/accounting.go` parses `tri` rows with
`strconv.ParseUint(...,10,64)`, the triangle is `[]uint64` (`sweep.go`), and
`combine`/`verify`/`writePerHeight` are all u64. Above ~a(25) the total wraps
silently. The n≤14 `ns-gate-u128` cannot catch it (values fit u64). The old
engine had an explicit `MAXN>64 requires --modp` guard.
Disposition: `CheckResultWidth` refuses maxn>25 at start (silent drop now
unreachable). Full big.Int widening of accounting→triangle→combine→verify is
deferred — only bites at a(26)+, which needs cloud.

**A3 · "The Absent Bouncer" — CRITICAL: the FR-7 counter-overflow "refuse at start" guard is documented but unimplemented. → FIXED `5597ad2`.**
`core/counter.h:12-14` states the orchestrator "must refuse at start" with an
undersized counter; no such check existed anywhere in `orchestrator/`.
`--counter u64 --maxn 30` ran for hours and wrapped silently.
Disposition: `CheckCounterWidth` enforces the documented limits (u64→a25,
u128→a48) at startup.

**A4 · "The Sealed Holes" — CRITICAL: holes are unreachable through the orchestrator. → DEFERRED (dedicated session).**
Old `build/tma_holes` produced the stratified per-(H,n,k) hole distribution at
scale (required deliverable AC-6). New: `MapArgs`/`RunMapWorker` (`worker.go`)
have no holes field, `keyLen` is hardcoded `H+2` in every Go path
(`runref.go:114,208,421`), `merge_worker.cpp` has no `--holes`, and the
seek-index *rejects* `H+3`.
Disposition: deferred to its own session. Holes remain reachable via the
standalone C++ `build/tma_holes` driver (`ns-gate-holes` passes). When threaded:
holes/keyLen `H+3` through MapArgs→worker.go→sweep.go→runref.go + `--holes` in
merge_worker + lift the seek-index `H+2`, plus D7's partition argument and a gate
beyond n=14.

**A5 · "The Credulous Adder" — HIGH: `combine` has no integrity guard — the exact bug that once produced a wrong a(22). → FIXED `f055cb9`.**
Old `gate-driver` proved combine refuses crashed/empty/corrupt/raced sweeps. New
`combine/main.go` globbed `h*.out`, silently `continue`d past unparseable rows,
and `--require-cover` only checked height presence.
Disposition: `addRow` now refuses a truncated (missing n==maxn row), zeroed, or
over-maxn shard; `runCombine` extracted and unit-tested.

**A6 · "Reader Without a Writer" — HIGH: mod-p residues have no producer. → DEFERRED (a23-future).**
Required for the a(23) deliverable (AC-5) and named in the risk table as the
overflow/divergence shadow. The new system only *reads* a residues file
(`verify.go`); nothing generates it.
Disposition: a real cross-check needs an independent producer (a mod-p counter
in the engine, or an independent enumerator) — substantial C++, far from the
a(21) frontier. The A3/A2 refuse-at-start guards already prevent *silent*
overflow in the reachable range, so this is belt-and-suspenders for a26+.

**A7 · "The Eroded Gauntlet" — MED: gate coverage shrank. → FIXED `311bdd1`.**
`ns-gates` omitted the `ns-gate-holes`/`verify`/`split` gates that exist (so A4
could rot undetected), and the old `gate-sym`/`gate-s2`/`gate-e0`/`gate-driver`
correctness checks had no new-system equivalent.
Disposition: wired holes/verify/split + a new `ns-gate-runfile` and `ns-gate-go`
(full Go suite, subsumes the A5 combine checks) into `ns-gates`. Porting the old
gate-sym/s2/e0/driver gates is left as follow-up.

## B. Sharp corners (magic-incantation class)

- **B1 · "The Amnesiac Checkpoint" — HIGH: resume trusts CLI flags over the checkpoint. → FIXED `6d44ac8`.** POLYCKPT stored no
  maxn/counter/fold/rev; resuming with a different `--maxn` silently corrupted
  the triangle. Now stamps config into POLYCKPT and hard-fails on mismatch.
- **B2 · "Coverage Optional" — HIGH: `combine --require-cover` defaulted false. → FIXED `2ccb0ee`.** A missing height shard
  → confidently-printed, too-low a(n). Default flipped to true.
- **B3 · "Seek Past the Guard" — HIGH: CRC is skipped on every *seeked* read** (`runfile.h`, `!seeked_`). → RESOLVED `62e8a0b`.
  Disposition: made an explicit verify-tool-only contract — the verify tool
  (`verify.go`, full-body CRC) and `runcat` are the corruption backstops, and B4
  removed the torn-file hazard. Per-stride sub-CRC declined to avoid hot-read-path
  changes on the frontier engine.
- **B4 · "The Torn Publish" — HIGH: run files weren't published atomically. → FIXED `4b12654`.** A SIGKILL during
  `finalize()` left a stale record-count + short CRC. Now temp+rename.
- **B5 · "The Toy RAM" — MED: `--ram` default 128 MB** forces spill-thrash. → FIXED `f091256` (warns below a 1 GiB floor; default unchanged).
- **B6 · "The Empty Pool" — MED: `Cores==0` deadlocks or returns a silent undercount. → FIXED `bec92b6`** (reject `Cores < 1`, which also absorbs negative `--cores`).
- **B7 · "The Double Tally" — MED: resume with an edited `--heights` silently double-counts. → FIXED `6d44ac8`** (hard-error if the checkpoint height isn't in `--heights`).
- **B8 · "Missing Reads as Empty" — MED: reader open-failure looked identical to empty input. → FIXED `aaf6e84`** (worker aborts on unreadable input; orchestrator surfaces worker stderr).
- **B9 · "The Quiet Default" — LOW: `predict` falls back to `R=4.4` on an unusable `--profile2`. → WONTFIX.**
  Not silent: the basis label `R=4.4 (default (profile2 unusable))` is printed on
  the headline line, so a reader sees the profile was rejected. Demoted LOW; the
  proposed "exit non-zero on an explicitly-passed unusable `--profile2`" is a nit
  left unaddressed.
- **LOW cluster:**
  - **"The Lenient Cat"** — `runcat` exited 0 on CRC mismatch. → FIXED `84ccc87`.
  - **"The Wrong Room"** — `verify`'s `--data-dir`/`--workers-dir` default to
    relative paths. → SKIPPED (it *fails loudly* — `cannot read`, exit 1 — so it's
    cwd-fragile but not silently wrong; absolute-path machinery not worth the churn).
  - **"The Fail-Open Counter"** — the seed writer defaulted any non-`u128` tag to
    u64. → FIXED `248f046` (reject unknown tags).
  - **"The Silent Truncator"** — `combine --maxn` smaller than the data silently
    dropped high-n rows. → FIXED `f055cb9` (refuse a nonzero n>maxn row).

## 2026-06-29 — a(23) H18 merge-stall findings (live diagnosis)

Surfaced while the live a(23) H18 col-2 sat for tens of minutes single-threaded
between map completion and merge spawn — one goroutine ~100% CPU, futex/kernel-
heavy, all map workers exited, `processed` frozen, ~2 GB heap. **Not** GC (heap
too small, Go GC can't pause that long) and **not** a deadlock (it drained and the
merge workers spawned). Read-only `/proc` diagnosis + a 3-pass code audit; the run
was **not touched**. Both are perf/correctness only (no semantics change); fixes
are **post-run** — we do not restart a healthy frontier job to optimize.

| Finding | What it is | Disposition |
|---|---|---|
| **Body Crawl** | Merge-cut sampling (`SampleKeysMulti`→`SampleKeys`, `runref.go:92-142`) opens each map output **unbuffered** and streams the **entire body** — ~3 read syscalls per record — only to pick `numCuts` evenly-spaced keys. Single-threaded in `mergePhase` (`sweep.go:780`) *before* any merge worker spawns. Seconds at a(20)/a(21) (small bodies); first bites at **a(23) H18** (multi-GB peak frontier → billions of records) = the stall. Ends exactly when it finishes → merge spawns. | **OPEN** — fix: sample from the `.idx` sidecar (1 key / 64 records → ~64× less I/O) instead of the body; at minimum wrap the fd in `bufio`. Confirm via `perf` on the next big column (hot stack should be `SampleKeys`/`read`). |
| **Magic Misread** | The Go `.idx` reader (`indexKeysInRange`, `runref.go:264`) does not skip the C++ self-describing header. C++ writes `magic('PLYI') + ver + bo` then `keyLen + count` (`runfile.h:226-239`); Go reads the 4-byte magic **as `keyLen`** → `kl != keyLen` → **always errors**. Effects: `SplitRangeByIndex` returns nothing (the seek-index steal path is dead — a contributor to `steals=0`), and the index can't be reused to fix Body Crawl. Comment at `runref.go:255` is stale (omits the magic). | **OPEN** — fix: skip + validate `magic(u32)+ver(u16)+bo(u8)` to match `runfile.h`; fix the comment. **RED-first** test (a real C++-written `.idx` the Go reader must parse). |

Notes:
- The other reason for `steals=0` is the **work-stealing tail miss** (record-based
  victim sizing, blind to compute-heavy keys) — see `docs/scheduling-design.md`
  (2026-06-29). Distinct from Magic Misread; both suppress steals.
- The **cond-herd livelock** two audit passes proposed is **ruled out** for this
  stall: `cond.Broadcast` fires only on unit completion (`sweep.go:667/698`) and
  `steals=0`, so a lone straggler/scan generates no broadcast churn.
- "Merge is cheap (seek-index)" is **false at scale** — Body Crawl never used the
  index, and Magic Misread broke it where it is used.
